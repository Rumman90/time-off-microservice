# Time-Off Microservice

Time-Off Microservice built with TypeScript, NestJS, TypeORM, SQLite, Outbox Pattern, Mock HCM integration, and Server-Sent Events (SSE).

The service manages employee leave requests while treating HCM as the official source of truth for leave balances.

# Important Note About API Gateway and SSE

Frontend connects to the API Gateway, not directly to the microservice.

```txt
Frontend
   ↓
API Gateway
   ↓
GET /time-off-requests/:id/events
   ↓
Time-Off Microservice
```

The SSE event is generated by the Time-Off Microservice.

The API Gateway only:

```txt
authenticates
routes
forwards the SSE stream
keeps connection open
handles TLS
applies rate limiting carefully
```

The API Gateway does not generate business events.

---

# Source of Truth

```txt
HCM = official leave balance source of truth
Local DB = request workflow source of truth
Local balance table = cached read model
```

The local balance cache improves read performance but is never treated as the final approval authority.

# Create Request Flow

```txt
Employee creates leave request
→ API Gateway forwards request
→ Time-Off Microservice stores request as VALIDATION_PENDING
→ Outbox job is created
→ API immediately returns requestId
→ Worker validates with HCM
→ Request becomes:
   PENDING
   or
   REJECTED
→ Microservice emits SSE event
→ API Gateway forwards SSE event to frontend
```

---

# Approval Flow

```txt
Manager approves request
→ Request becomes HCM_SYNC_PENDING
→ Outbox job is created
→ Worker sends deduction to HCM
→ Request becomes:
   APPROVED
   or
   HCM_SYNC_FAILED
→ Microservice emits SSE event
→ API Gateway forwards SSE event to frontend
```

---

# Frontend Synchronization Strategy

Primary mechanism:

```txt

```

# Idempotency Strategy

Each leave request generates a unique idempotency key.

The same key is reused during retries to prevent duplicate HCM deductions.

Protected scenarios:

```txt
network retry
duplicate approval click
worker restart
timeout retry
duplicate HCM call
```

# Scalability Considerations

If traffic spikes occur:

```txt
100,000 employees creating leave requests simultaneously
```

The system avoids direct synchronous HCM calls.

Instead:

```txt
API stores requests quickly
→ Worker processes gradually
→ HCM protected from overload
```

In production, the DB-backed outbox can be replaced with:

```txt
RabbitMQ
Kafka
AWS SQS
Azure Service Bus
```

# Production Notes

In real production:

```txt
API Gateway should disable response buffering for SSE.
API Gateway should allow long-lived connections.
API Gateway should forward auth/user context.
API Gateway should forward correlation IDs.
API Gateway should not aggressively timeout SSE streams.
```

The assessment keeps SSE inside the Time-Off Microservice and documents API Gateway as production infrastructure.
